# CRIC Open-Source Governance Specification

## Purpose

CRIC is intended to become a durable scientific and technical commons rather than a repository whose meaning depends on one organisation or one development team.

Governance must preserve openness while protecting ontology stability, scientific integrity, provenance and safety boundaries.

---

# Governance Principles

- transparent decisions;
- open contribution;
- evidence-based scientific discussion;
- stable machine contracts;
- explicit maintainer authority;
- documented conflicts;
- reversible decisions;
- public change history.

---

# Governance Domains

Separate governance should exist for:

- software;
- ontology;
- knowledge;
- datasets;
- models;
- agents;
- safety-relevant interpretation.

One approval rule should not govern everything.

---

# Roles

## User

Consumes CRIC.

## Contributor

Submits code, knowledge, data or documentation.

## Reviewer

Reviews contributions in a defined competency area.

## Domain Reviewer

Reviews scientific/domain-specific contributions.

## Ontology Reviewer

Reviews semantic changes.

## Maintainer

Maintains a repository/component.

## Core Maintainer

Approves stable changes to CRIC Core contracts.

---

# Maintainer Authority

Maintainers may:

- merge eligible pull requests;
- manage releases;
- enforce repository policy;
- revert harmful changes;
- approve role assignments.

They must not silently rewrite historical scientific evidence.

---

# Scientific Governance

Scientific disagreements should be represented in the graph where appropriate rather than resolved solely through repository politics.

A repository may accept two contradictory claims if both are validly sourced and represented.

---

# Ontology Governance

Stable core ontology changes require:

- proposal;
- evidence;
- impact analysis;
- tests;
- review;
- version change.

---

# Decision Records

Important architecture/governance decisions should use ADRs or equivalent.

---

# Code of Conduct

CRIC should adopt an open-source code of conduct supporting respectful technical and scientific disagreement.

---

# Conflict of Interest

Reviewers should disclose material conflicts for high-impact scientific decisions where applicable.

---

# Security Governance

Security vulnerabilities should have a private reporting route.

Sensitive vulnerabilities should not require immediate public issue disclosure.

---

# Safety Governance

CRIC's public software may support decision intelligence, but operational warning authority remains with competent institutions.

---

# Project Stewardship

The founding organisation may initially act as steward and appoint maintainers.

The governance model should permit broader institutional and scientific participation as the project matures.

---

# Governance Evolution

Governance itself should be versioned and open to amendment through documented proposals.

---

# v0.1 Acceptance Criteria

- governance roles documented;
- maintainer responsibilities defined;
- ontology governance linked to PR process;
- scientific contradiction policy exists;
- security reporting route defined;
- contribution and conduct documents exist.
